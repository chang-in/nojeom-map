# 설계

노점상 커뮤니티 맵. 붕어빵·떡볶이 같은 길거리 노점 위치를 제보하고 지도에서 찾는다.

> 이 문서는 **왜 그렇게 했는지**를 담는다. 컬럼 목록·시그니처처럼 코드를 읽으면 아는 것은
> 적지 않는다 — 적는 순간 코드와 어긋나고, **어긋난 문서는 읽는 쪽이 거짓을 사실로 받는다.**

## 데이터 모델

컬럼 목록은 `supabase/migrations/`에 있다.

```
stall          정확한 좌표를 담는다. anon은 SELECT 정책이 없어 아예 못 본다
stall_public   trunc(,4) 흐린 좌표 + active만. anon은 이것만 본다 (뷰)
```

읽는 쪽은 **항상 `stall_public`** 이다. 이유는 아래 "좌표를 흐리는 자리가 DB인 이유".

## 인터페이스

```
GET  /api/stalls?bbox=west,south,east,north&limit=100
     → [{ id, kinds, name, lat, lng, lastConfirmedAt }]   lat/lng는 흐린 값
POST /api/stalls  { kinds, name?, lat, lng }  → 201 { 생성된 전체 객체 }
POST /api/stalls/:id/reports  { reason }      → 202   접수 즉시 status=hidden
```

## 상태 — 첫 바퀴

| 상태 | 무엇이 보이나 | 다음에 뭘 할 수 있나 |
|---|---|---|
| 정상 | 지도 + 마커 | 마커 클릭 · 지도 클릭해 제보 |
| **빈** | 마커 0개 | "아직 제보가 없어요. 지도를 눌러 첫 제보를" |
| 로딩 | 지도는 뜨고 마커만 대기 | — |
| **실패** | "불러오지 못했어요" | **다시 시도** |
| **위치 거부** | 서울시청 기준으로 시작 | 직접 이동 (실패가 아니다 — 정상 이용 가능) |
| 제출 중 | 버튼 비활성 | — |
| **너무 축소됨** | 마커 숨김 | "지도를 더 확대해 주세요" |

2바퀴로 미룸: 타일 로드 실패 · 근접 중복 의심 · 오프라인 재시도

# 왜 이렇게 했나

## `kinds`가 배열인 이유

실제 노점은 **복합 메뉴가 대부분**이다 (붕어빵+어묵, 떡볶이+순대+튀김).
단일 값으로 두면 사용자가 같은 자리에 '붕어빵 핀'과 '어묵 핀'을 따로 찍어 **중복 마커가 쌓인다.**
`text` → `text[]`는 데이터가 쌓인 뒤엔 마이그레이션이라 **처음에 정해야 하는 부류**다.

## `status`와 `lastConfirmedAt`이 있는 이유

노점은 **계절·날씨·단속·자리 이동이 잦다.** `createdAt`만 있으면 오래된 마커가 계속 살아남아
**몇 달 뒤 지도가 유령 핀으로 뒤덮인다.** 그러면 지도 자체를 못 믿게 된다.

`status`는 소프트 삭제용이기도 하다 — 삭제 요청이 오면 지우지 않고 `hidden`으로 돌린다.
잘못된 신고였을 때 되돌릴 수 있어야 한다.

## `bbox`를 처음부터 넣은 이유

지도 이동마다 보이는 영역만 조회한다. **나중에 넣으면 부르는 쪽을 전부 고쳐야 한다** —
되돌리기 비싼 결정이라 첫 바퀴에 박았다. Leaflet의 `map.getBounds()`와 1:1로 맞는다.

순서는 **`west,south,east,north`**. 남북·동서가 뒤집힌 입력은 거부한다.

## `limit`이 있는 이유

사용자가 지도를 축소해 전국을 보는 순간 **수천 개 마커가 한 번에 내려온다.** 서버 타임아웃과
브라우저 렉으로 이어진다. `limit`과 "너무 축소됨" 상태는 **한 쌍**이다.

## POST가 전체 객체를 돌려주는 이유

`{id}`만 주면 제보 직후 다시 GET해야 한다. 전체 객체를 주면 **재조회 없이 마커를 즉시 꽂는다.**

## 좌표를 흐리게 공개하는 이유 ★ 이 제품의 핵심 제약

노점상은 **무허가 영업인 경우가 많다.** 정확한 위치 공개가 단속·민원의 도구가 될 수 있다.

> ⚠️ **"실제로 그런 사례가 있었나"는 확인하지 못했다.** 설계 리뷰에서 한 모델은
> '가슴속 3천원'·당근 '겨울간식지도'의 단속 사례를 들었지만, 다른 모델이 웹을 검색하고
> **확인 가능한 사례를 찾지 못했다.** 사례는 미확인으로 두되, **가능성만으로도 예방한다.**

공개 좌표는 **소수점 4자리(≈11m)** 로 자른다. 정확한 값은 DB에만 둔다.

### 좌표를 흐리는 자리가 DB인 이유 — 앱이 아니다

처음엔 앱의 `toPublicStall`이 흐렸다. **그건 우회된다.**
`anon` 키는 브라우저에 노출되므로 클라이언트가 우리 API를 안 거치고 PostgREST를 직접
부르면 그만이다 (실측 2026-08-31: `lat=37.5665123`이 그대로 나왔다).

**RLS로도 못 막는다 — RLS는 행 단위지 열 단위가 아니다.** `hidden` 행은 걸러도
`active` 행의 좌표 열은 나간다. 그래서 `stall`의 anon SELECT를 없애고
흐린 좌표만 담은 `stall_public` 뷰를 공개한다(`security_invoker = false`).

DB의 `trunc(,4)`는 `lib/geo.ts`의 `blurCoord`와 **같은 규칙**이다 — 반올림이 아니라
잘라내기여서 어느 경로로 읽어도 값이 같다.

⚠️ 그 결과 **`toPublicStall`·`blurCoord`는 라우트에서 안 쓰인다.** 뷰가 같은 일을 한다.
지우지 않은 건 관리 기능이 `service_role`로 `stall`을 직접 읽게 되면 필요해서다.
그 경로가 안 생기면 지운다.

| 후보 | 결과 |
|---|---|
| 소수점 6자리 (정확) | 건물·노점 단위 특정 → 위험 |
| **소수점 4자리 ≈ 11m** ← 선택 | 골목 어귀까지 안내됨. 건물 단위 특정은 막힘 |
| 50~100m | 상인 보호는 강하지만 **찾을 수 없어 제품 가치가 사라진다** |

같은 이유로 **"현재 영업중"이라고 쓰지 않는다.** `lastConfirmedAt` 기반으로 **"최근 제보됨"**
으로만 표현한다 — 실시간 영업 여부를 단정하면 상인의 현재 위치를 알려주는 셈이 된다.

## 삭제 요청을 첫 바퀴에 넣는 이유

**제보 대상이 자기를 뺄 방법이 없는 채로 배포하면 안 된다.** 로그인 없이 누구나 요청할 수 있고,
접수 즉시 `hidden`으로 돌린 뒤 검토한다. 최소 형태라 비용이 작고, 없을 때의 위험이 크다.

## PostGIS를 지금 안 쓰는 이유

한국 대상이고 데이터가 수만 건 이하면 `lat BETWEEN … AND lng BETWEEN …` 범위 쿼리와
`(lat, lng)` 복합 인덱스로 충분하다. 반경 검색·거리순이 필요해지면 Supabase에서
`CREATE EXTENSION postgis;` 한 줄로 전환할 수 있어 **지금 감수할 복잡도가 아니다.**

## DB가 Supabase인 이유

⚠️ **Vercel Postgres는 신규 제공이 끝났다** (기존 DB는 2024-12에 Neon으로 이전).
새 프로젝트는 Marketplace에서 붙인다. Supabase를 고른 건 무료 티어로 시작할 수 있고
**PostGIS 확장 경로가 열려 있어서**다.

## 지도가 Leaflet + OSM인 이유, 그리고 주의

API 키 없이 첫 바퀴를 시작할 수 있다. 카카오·네이버는 키 발급과 도메인 등록이 선행돼야 한다.

⚠️ **OSM 기본 타일 서버는 SLA가 없고 사용량이 많으면 차단될 수 있다.**
attribution 표시는 필수이고, 트래픽이 늘면 전용 타일 제공자로 옮길 계획이 필요하다.
→ [OSM Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/)
